# 动态视频清透玻璃启动器 UI 设计

## 目标

统一登录页与登录后主页的视觉语言，并解决启动时旧背景图片先闪现、随后才切换视频的问题。

最终采用：

- 登录页：已确认的 **I 方案——高质感清透玻璃**。
- 登录后主页：已确认的 **B 方案——沉浸悬浮控制台**。
- GM 查询：已选择 **A 增强方案——高质感晶体玻璃 + 左侧纯文字一级分类**。
- 两个页面始终使用本地 `assets/launcher-background.mp4` 作为动态背景。
- 保留并默认开启背景视频原声，暂不接入独立背景音乐。
- 玻璃区域保持背景原画清晰，不使用会模糊整片视频的 `backdrop-filter: blur(...)`。
- 登录、主页和 GM 入口均支持窗口缩放后的响应式布局。

## 范围

本次包含：

1. 移除登录页和主页的旧背景 `<img>`、视频 `poster` 及图片优先显示链路。
2. 让一个共享的本地 MP4 视频元素在 HTML 首次解析时就开始预加载并成为两个页面的唯一背景媒体。
3. 重做登录页视觉样式为右侧高质感清透玻璃面板。
4. 重做登录后主页为沉浸悬浮控制台。
5. 让右上角声音按钮只控制视频原声的静音和音量；不增加视频关闭按钮。
6. 保留现有登录、账号切换、区服选择、多开、开始游戏和 GM 查询功能。
7. 将 `GM 道具查询`作为登录成功后才出现的文字按钮放入主页底部控制台。
8. 将版本升级到 `1.0.4`，更新测试并重新构建安装包、便携包和 `update.json`。
9. 将 GM 查询窗口升级为 A 增强方案，并保留现有数据库、分类和 IPC 查询链路。

本次不包含：

- 修改 GM 道具数据库结构、分类映射或查询接口。
- 修改游戏服务端协议或游戏启动参数。
- 引入新的远程视频、远程皮肤、在线音乐播放器或第三方 UI 依赖。
- 下载、嵌入或播放《游京》及其他独立背景音乐。

## 视觉规范

### 共同材质

- 主色只使用中性透明层、冰青色和白色，不再使用固定蓝紫面板或金色主按钮。
- 玻璃质感由以下效果组成：
  - 双层高光描边；
  - 斜向镜面反射；
  - 细微透明纹理；
  - 内外阴影形成的折射层次；
  - 输入框和按钮的顶部晶体高光。
- 大面积玻璃容器必须保持 `0px` 背景模糊。
- 透明暗层只用于保证文字可读，不得遮蔽视频主体。
- 动画和交互高光不得影响登录输入、窗口拖动或主要按钮点击。

### 登录页

- 视频铺满整个窗口。
- 右侧登录面板占桌面宽度约 31%，从顶部延伸到底部。
- 面板无固定色相，视频颜色直接透出。
- 账号、密码、记住密码、自动登录、忘记密码、扫码登录和快捷登录沿用现有行为。
- 登录按钮使用冰青晶体样式。
- 声音、菜单、最小化和关闭按钮位于右上角。
- 页面不再显示登录页底部的“未找到游戏”或开始游戏占位控制栏。

### 登录后主页

- 使用 **B 方案——沉浸悬浮控制台**。
- 顶部为离窗口边缘留有间距的悬浮玻璃栏：
  - 左侧为 `Kiss`；
  - 中部保留必要的官网、活动、公告和教程文字入口；
  - 右侧为账号、切换账号、声音、菜单、最小化和关闭。
- 页面主体尽量完整展示背景视频，不叠加大面积活动卡片。
- 底部上方显示一条轻量公告信息流。
- 底部悬浮控制台依次包含：
  - 当前账号、客户端状态和游戏目录摘要；
  - `GM 道具查询`文字按钮；
  - 活动入口；
  - 多开管理；
  - 区服选择；
  - 冰青色“开始游戏”主按钮。
- 现有时间线不再作为常驻大面积组件；重要版本状态合并到状态摘要或公告信息流中。
- 点击“活动入口”后，在控制台上方打开清透玻璃活动浮层，复用现有主横幅、次横幅和公告数据；点击外部或按 `Escape` 关闭。

### GM 查询

- 采用 A 增强方案，窗口使用无背景模糊的高质感晶体玻璃：
  - 双层折射亮边；
  - 弧面镜面反射；
  - 细密透明玻璃纹理；
  - 卡片内凹高光；
  - 冰青色选中辉光。
- 左侧只显示纯文字一级分类，不使用分类图标：
  - 全部；
  - 赛车；
  - 赛车皮肤；
  - 赛车装扮；
  - 服饰；
  - 宠物；
  - 道具；
  - 社交展示；
  - 宝石；
  - 水族；
  - 系统/其他。
- 选择一级分类后，右侧二级分类才显示对应内容。例如：
  - 赛车：S、A、B、C、D、T 机甲、K 轮滑、M 摩托等；
  - 服饰：套装、上装、下装、发饰、头饰、鞋子、背饰、面饰等；
  - 宠物：宠物、宠物道具、精灵卡、精灵道具、宠物头饰、宝宝服饰等。
- 顶部保留名称/ID 搜索、二级分类、性别、ID 大小排序、查询和重置。
- 道具图片继续使用 `http://iips.speed.qq.com/images/{id}.png`，加载失败时显示“暂无图片”，不得影响其他卡片。
- 标准窗口每页 30 条，显示为 10 列 × 3 行。
- 卡片显示图片、名称、ID 和二级分类；点击复制 ID 的现有行为继续保留。

## 响应式行为

### 宽屏与标准窗口

- 登录面板保持约 31% 宽度，并设置合理的最小宽度。
- 主页顶部栏、公告条和底部控制台保持单行。
- 背景视频使用 `object-fit: cover`，窗口缩放时不产生空白边。

### 中等宽度

- 登录面板逐步增加到约 38%～42%，输入区保持可用宽度。
- 主页顶部次要导航自动隐藏或收进现有菜单。
- 底部控制台允许换成两行：
  - 第一行显示状态摘要；
  - 第二行显示 GM、活动、多开、区服和开始游戏。
- “开始游戏”始终保持最明显的视觉层级。
- GM 网格变为 8 列，每页同步调整为 24 条，继续保持 3 行并允许结果区域内部滚动。

### 小窗口

- 登录页优先保证登录表单完整可见，必要时降低装饰反射强度并压缩间距。
- 主页隐藏非必要公告详情，只保留公告标题。
- 底部操作区可滚动或紧凑换行，但不得遮挡窗口控制按钮。
- GM 按钮保持纯文字，不改成仅图标入口。
- GM 网格变为 6 列，每页同步调整为 18 条，继续保持 3 行并允许结果区域内部滚动。

## 媒体链路

### 首帧与旧图移除

- 从登录页移除 `loginMediaImage`。
- 从主页移除 `homeHeroImage`。
- 在 `#app` 内建立一个位于登录页和主页下方的共享 `<video id="launcherBackgroundVideo">`。
- 共享视频在 HTML 中直接设置本地 MP4 `src`，并包含 `autoplay`、`loop`、`playsinline` 和 `preload="auto"`。
- 不设置 `poster`，不再从内容配置写入旧图片地址。
- `MediaController` 不再执行“先显示图片、视频可播后切换”的状态机。
- 页面切换不替换、不重载也不暂停共享视频，因此视频画面和声音保持连续。

### 声音

- 共享背景视频默认开启原声，默认音量为 70%。
- 右上角只显示一个声音按钮，负责视频原声静音与恢复；音量浮层只调节视频音量。
- 用户的视频静音和音量偏好继续持久化。
- 不加载 `launcherMusic`、SoundCloud 或其他独立音乐源。
- 若 Chromium 阻止首次有声自动播放，在第一次鼠标或键盘交互时重试，不得把临时播放失败永久保存为静音偏好。
- 页面不可见时暂停视频，恢复可见时继续播放。

### 视频异常

- 本地视频无法加载时显示中性深色背景和简短状态提示。
- 不回退到旧背景图片。
- 登录、GM 查询和开始游戏等核心功能仍可使用。

## 功能与权限边界

- 未登录时不渲染或隐藏 GM 入口。
- 登录成功、主页显示后才展示 `GM 道具查询`按钮。
- 登出后立即隐藏 GM 入口并关闭已打开的 GM 查询窗口。
- GM 的主入口从设置菜单移动到底部控制台，设置菜单不再保留重复入口。
- GM 按钮继续调用现有查询弹窗，不改变 IPC 和数据库访问边界。
- 标题栏关闭、`Alt+F4`、托盘菜单和游戏启动后的自动隐藏继续使用已实现的独立关闭逻辑，不因本次视觉调整而改变。

  - 适配新的主页 DOM；
  - 控制活动浮层的打开、外部点击关闭和 `Escape` 关闭；
  - 适配 GM 新布局，保持现有查询、排序、分页和复制 ID 行为；
  - 保持 GM 仅登录后可见以及登出清理行为。
- 测试文件
  - 更新 DOM、媒体、响应式、GM 权限和打包边界断言。

## 错误处理

- 任何媒体错误都只影响背景展示，不应阻断账号登录。
- 动态内容加载失败时，公告条显示现有离线或加载失败文案。
- 游戏目录未选择、区服未就绪或客户端状态异常时，“开始游戏”维持现有禁用状态和说明。
- GM 数据库缺失或查询失败时，继续由现有 GM 弹窗展示错误，不让主页崩溃。

4. 媒体控制器不再执行图片回退。

8. 登录页与主页的大面积玻璃容器不使用背景模糊。
9. 主要 UI 不再使用原有金色或固定蓝紫色主题。

### 运行验证

2. 视频从首次页面渲染起就是唯一背景。

4. 右侧登录玻璃和主页悬浮栏后的背景细节保持清晰。

## 回滚

- 所有更改限制在 Electron 启动器和对应测试中。
- 若新布局出现严重问题，可恢复旧 HTML/CSS 结构和媒体控制器，但不得恢复已确认要移除的旧图片闪屏行为。
- 重新构建前保留当前 1.0.3 发布产物，避免未验证的新产物覆盖唯一可用版本。
