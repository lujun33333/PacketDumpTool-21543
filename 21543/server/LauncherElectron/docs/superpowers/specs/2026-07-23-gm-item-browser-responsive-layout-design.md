# GM 道具查询与启动器响应式布局设计

## 1. 目标

在现有 Electron 启动器中加入只读 GM 道具查询界面，并把固定 `1601×910` 的窗口和页面改为可缩放的响应式布局。

本次交付只负责查询、筛选、查看图片和复制道具 ID，不包含向账号发放道具、修改角色数据或其他数据库写操作。

## 2. 已确认需求

- GM 查询仅在账号登录成功后可见、可打开。
- 退出登录或登录会话失效时，已打开的 GM 窗口立即关闭并清空查询状态。
- GM 入口放在登录后可用的启动器设置菜单中。
- GM 采用覆盖主页的大型模态窗口，不离开当前启动器页面。
- 一级分类栏去掉图标，只保留中文文字。
- 默认视口显示 10 列、3 行，共 30 个道具卡片。
- 窄窗口自动改为 8 列或 6 列，始终尽量保留 3 行：分页大小依次为 30、24、18。
- 支持按道具 ID“从小到大”和“从大到小”排序，默认从小到大。
- 道具图片使用 `https://iips.speed.qq.com/images/{ID}.png`。
- 启动器默认窗口调整为 `1280×720`，最小窗口为 `1024×640`，允许自由缩放和最大化。

## 3. 界面设计

### 3.1 GM 入口与权限状态

登录成功后的设置菜单增加“GM 道具查询”。登录页不渲染该入口，renderer 不能仅靠修改 DOM 绕过限制：main 进程的每个 GM IPC handler 都必须再次检查当前已认证会话。

会话退出时：

1. main 发出已有的用户退出事件；
2. renderer 关闭 GM 模态窗口；
3. 清除关键字、分页和当前结果；
4. 后续查询由 main 返回稳定的“请先登录”错误。

### 3.2 GM 模态窗口

- 尺寸：`width: min(94vw, 1380px)`，`height: min(88vh, 780px)`。
- 最小视口下不超出窗口，结果区内部滚动，页脚始终可见。
- 标题栏包含“GM道具查询”和关闭按钮。
- `Escape` 关闭；焦点保持在模态窗口内；关闭后焦点返回 GM 菜单入口。

### 3.3 筛选区

顶部筛选区包含：

1. 名称或 ID 输入框；
2. 二级分类下拉框；
3. 性别下拉框；
4. 排序下拉框：`ID 从小到大`、`ID 从大到小`；
5. “查询”和“重置”按钮。

查询语义：

- 纯数字关键字按精确 ID 查询；
- 其他关键字按名称包含匹配；
- 一级分类是大类，二级分类只能从当前一级分类所属的子类中选择；
- 一级分类改变后，二级分类立即重建并恢复为该大类的“全部”选项；
- 一级分类、二级分类、性别均使用数据库实际值生成的严格白名单；
- 切换筛选条件、排序方式或网格列数后重置到第 1 页。

### 3.4 一、二级分类联动

左侧一级分类只显示文字，不显示图标。顺序为：

- 全部道具
- 赛车
- 赛车皮肤
- 服饰
- 宠物
- 道具
- 赛车装扮
- 社交展示
- 宝石
- 水族
- 系统/其他

当前一级分类使用金色文字和低透明度金色背景。二级分类不是一套全局固定选项，而是跟随一级分类动态变化：

| 一级分类 | 对应二级分类示例 |
| --- | --- |
| 赛车 | 全部赛车、A级赛车、B级赛车、C级赛车、D级赛车、S级赛车、M1/M2/M3、L0/L1/L2/L3、T1/T2/T3、K0/K1/K2、R级赛车、特殊赛车等 |
| 赛车皮肤 | 全部赛车皮肤、赛车皮肤 |
| 服饰 | 全部服饰、套装、上装、下装、发饰/头发、头饰、面饰、护镜、表情、手套、背饰、尾饰、鞋子、坐骑、飞饰及各类服饰光效等 |
| 宠物 | 全部宠物、宠物、宠物道具、精灵卡、精灵道具、宠物头饰、宝宝头饰、宝宝炫光、宝宝服饰 |
| 道具 | 全部道具、礼包、功能道具、宝箱、钥匙、抽奖卡、兑换道具、增值道具及其他功能卡 |
| 赛车装扮 | 全部赛车装扮、车辆炫光、喷漆、车牌、尾挂/气球、车头、车尾/尾翼、侧翼、车轮/车胎、胎印、漂焰、改装配件等 |
| 社交展示 | 全部社交展示、前景、背景、头像、头像框、名片、聊天气泡、戒指、进房特效、表情挂饰等 |
| 宝石 | 全部宝石、圆形竞速宝珠、三角道具之钻、祝福石、幸运石、雕刻刀、宝石拆除刀 |
| 水族 | 全部水族、鱼儿、鱼苗、鱼饲料 |

界面显示名可以更友好，例如数据库值 `发饰` 显示为“发饰/头发”，但传给 main 的查询值仍是数据库中的规范值。

明确查询规则：

- 一级选择“赛车”、二级选择“全部赛车”：`category = 赛车`，返回全部 2,081 辆赛车，不包含赛车皮肤；
- 一级选择“赛车”、二级选择“S级赛车”：`category = 赛车 AND subcategory = S级赛车`；
- 一级选择“服饰”、二级选择“套装”：`category = 服饰 AND subcategory = 套装`；
- 一级选择“服饰”、二级选择“上装”：`category = 服饰 AND subcategory = 上装`；
- 一级选择“服饰”、二级选择“发饰/头发”：实际查询 `category = 服饰 AND subcategory = 发饰`；
- 一级选择“全部道具”时，二级下拉框显示“全部二级分类”并禁用，不附加分类条件。

### 3.5 道具卡片网格

每张卡片包含：

- 道具图片；
- 单行名称，溢出显示省略号并提供完整 `title`；
- 数字 ID；
- “复制ID”按钮。

网格规则：

| GM 结果区可用宽度 | 列数 | 每页数量 |
| --- | ---: | ---: |
| `>= 1000px` | 10 | 30 |
| `720px–999px` | 8 | 24 |
| `< 720px` | 6 | 18 |

Electron 窗口最小宽度为 `1024px`，正常安装态主要覆盖 10 列和 8 列；6 列作为浏览器缩放、极端 DPI 或未来嵌入场景的兜底。

图片规则：

- URL 只能由经过验证的正整数 ID 组合生成，renderer 不接受服务端或用户提供的任意图片 URL；
- 使用 HTTPS、懒加载和 `referrerpolicy="no-referrer"`；
- 图片加载失败时显示本地统一占位图，不影响查询与复制 ID；
- 图片错误不触发无限重试。

### 3.6 分页

页脚显示总条数、当前页、总页数、上一页和下一页。main 返回总条数，renderer 根据当前列数传入固定白名单分页大小 `30/24/18`。页码越界时 main 做边界归一或返回空页，不拼接任意 SQL。

## 4. 启动器响应式布局

### 4.1 BrowserWindow

- 默认内容尺寸：`1280×720`；
- 最小尺寸：`1024×640`；
- `resizable: true`；
- `maximizable: true`；
- 保持无边框窗口、现有托盘、关闭确认和安全 `webPreferences` 不变。

### 4.2 登录页

- 移除 `html/body` 和 `.shell` 的固定 `1601×910` 最小尺寸。
- `.shell` 使用 `100vw × 100vh`。
- 登录栏宽度使用 `clamp(330px, 32vw, 430px)`。
- 登录栏内边距、图标、按钮高度和协议区域根据视口高度分级压缩。
- 背景图/视频继续使用 `object-fit: cover`，不拉伸。
- 高度不足时登录栏内容允许自身滚动，窗口整体不出现滚动条。

### 4.3 登录后主页

- 顶部导航、活动内容、底部时间线、区服和开始按钮改为弹性布局。
- 大屏尽量保持当前官服比例；中等宽度压缩间距和活动卡尺寸；小宽度隐藏非关键长文案，但保留账号、设置、区服、开始游戏及 GM 入口。
- 服务器、多开、关闭确认和 GM 模态窗口都使用 `max-width/max-height` 与视口边界约束。
- 不通过 Chromium `zoom` 整页缩放，避免文字和点击区域模糊；仅对装饰性尺寸使用 CSS 变量和 `clamp()`。

## 5. 数据与 IPC 架构

### 5.1 数据库位置

- 开发态：`resources/gm-items.sqlite3`；
- 安装态：通过 `extraResources` 放到 `process.resourcesPath/gm-items.sqlite3`；
- main 进程以只读方式打开；renderer 和 preload 不取得文件路径或 SQLite 对象。

### 5.2 查询模块

新增独立 main/shared 查询模块，职责为：

- 解析并验证查询参数；
- 从数据库返回一级分类，并按选中的一级分类返回它所属的二级分类及数量；
- 使用参数化 SQL 查询；
- 对排序字段、排序方向和分页大小做枚举白名单；
- 限制关键字长度和返回字段；
- 关闭应用时释放只读数据库连接。

允许返回的道具字段仅为：`id`、`name`、`category`、`subcategory`、`gender`。

### 5.3 IPC 契约

计划增加两个具名接口：

- `launcher:get-gm-catalog`：返回可用分类、二级分类和性别选项；
- `launcher:query-gm-items`：返回筛选后的分页结果和总数。

边界要求：

- main handler 执行现有 sender 信任校验；
- main handler 执行登录会话校验；
- preload 只暴露两个具名函数，不暴露 `ipcRenderer`；
- renderer 不直接读取文件、数据库或 Node API；
- 错误返回稳定的用户可读消息，不暴露本地路径和 SQL 内容。

## 6. CSP 与网络图片

只扩展图片来源，允许 `https://iips.speed.qq.com`；不增加远程脚本、frame、XHR 或 Node 权限。所有导航和新窗口仍由现有 main 进程策略拦截。

若目标网络无法访问图片域名，GM 查询仍能正常工作并显示占位图。

## 7. 错误状态

- 未登录：不显示入口；IPC 调用返回“请先登录后使用 GM 道具查询”。
- 数据库缺失或损坏：GM 模态窗口显示“道具数据库不可用”，不影响登录和启动游戏。
- 查询无结果：显示空状态并保留筛选条件。
- 图片失败：单卡片显示占位图。
- 复制失败：显示短暂错误提示，不影响其他卡片。
- 查询进行中：禁用重复查询并显示轻量加载状态。

## 8. 测试与验收

实现遵循 TDD，至少覆盖：

1. 查询服务对一级/二级分类联动、关键字、性别、分页、ID 升序和降序的行为；
2. 非法排序、超长关键字、非法分页大小和未登录请求被拒绝；
3. 一级“赛车”返回全部赛车且排除赛车皮肤，二级“S级赛车”只返回 S 级；
4. 一级“服饰”的二级选项包含套装、上装、下装和发饰，选择后只返回对应服饰；
5. preload 只暴露最小 GM API；
6. 登录前无 GM 入口，登录后显示，退出登录自动关闭；
7. 10/8/6 列分别映射 30/24/18 条；
8. 图片 URL 只由数字 ID 生成，失败后使用本地占位图；
9. BrowserWindow 默认/最小尺寸和可缩放配置；
10. `1024×640`、`1280×720`、`1600×900` 三种视口 smoke；
11. SQLite 完整性、打包资源存在性和安装态只读查询；
12. 全量单元测试、语法检查和现有 renderer flow smoke 不回归。

## 9. 回滚与影响边界

- GM 功能通过独立查询模块、IPC 和 renderer 组件接入，可删除对应入口与资源恢复。
- 数据库只读，不执行迁移或用户数据写入。
- 响应式改动集中在主窗口配置与 renderer CSS；保留现有登录、启动游戏、托盘、关闭确认、多开和更新流程。
- 若安装态 SQLite 不可用，启动器主体继续工作，GM 功能单独降级。
